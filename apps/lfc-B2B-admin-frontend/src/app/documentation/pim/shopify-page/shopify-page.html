Comment le référentiel pousse vers Shopify sans jamais casser une URL — et le seul réglage qui reste à faire à la main.

Push idempotent, SEO-safe. Une fois une collection ou un produit créé, on ne le recrée jamais : on le met à jour par id. Le handle Shopify — donc l'URL, donc le référencement — reste intact.

Le handle est calculé une seule fois, à la création. Modifier le contenu (titre, textes, images, prix) ne le change pas. Le push suit donc un upsert piloté par le binding.

La table de correspondance id + handle. Elle décide create (première fois) vs update (ensuite), et garde le lien vers la bonne ressource Shopify.

Une empreinte du dernier contenu poussé. Inchangée → on saute l'appel. Moins d'écritures, pas de churn inutile côté Shopify.

Si un handle doit vraiment changer, on pose une redirection 301 pour ne pas perdre le jus SEO. Par défaut : on ne touche pas au handle.

Config manuelle, une seule fois. Les tax overrides ne sont pas pleinement pilotables par API : le PIM crée les collections TVA programmatiquement, mais le mapping collection → taux se règle à la main dans l'admin (Réglages → Taxes et droits de douane).
